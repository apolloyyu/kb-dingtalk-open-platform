# 多 Agent 垂直专家协同

## **场景介绍**

项目推进过程中，团队成员经常需要临时咨询不同领域的专业问题——问HR请假政策有几天年假、问法务合同里的排他条款有没有风险、问财务出差住宿报销上限是多少，每次都要在通讯录里找人、发消息等回复，效率很低。多 Agent 垂直专家群协同方案将 HR Agent、法务 Agent、财务 Agent、技术 Agent 等多个领域专家同时部署在同一个项目群中，群成员只需 @对应的 Agent 即可获得即时专业支持。每个 Agent 接入各自领域的专属知识库和 SkillHub 能力，通过差异化的图标和卡片样式让回复来源一目了然，真正实现"群里就有专家团队随时待命"。

## **适用场景**

本方案的核心架构是"一个群部署多个 Agent → 各 Agent 独立知识库 + 独立 SkillHub → 差异化卡片回复"，除项目群多专家协同外，以下场景也可以复用同一套架构，只需调整 Agent 数量、知识库内容和 Skill 订阅即可：

以下为两个典型交互场景的对话示意：

![image.png](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/5613051871/p1081513.png)

| **场景** | **部署的 Agent 组合** | **典型交互示例** |
| --- | --- | --- |
| 创业公司全能群 | HR + 财务 + 法务 + 行政 | "@HR助手 社保基数什么时候调整""@行政助手 帮我订明天的会议室" |
| 研发项目群 | 技术文档 + 运维 + 测试 + 产品 | "@运维助手 生产环境昨晚报了什么告警""@产品助手 V3.2的需求文档在哪" |
| 销售作战群 | 产品知识 + 竞品分析 + 报价 + 合同 | "@竞品助手 和XX产品比我们的优势是什么""@合同助手 标准合同模板发一份" |
| 客服支撑群 | 售前咨询 + 售后支持 + 技术排障 | "@售后助手 客户反馈的退货流程是什么""@技术助手 这个错误码是什么意思" |

## 钉钉集成能力

多 Agent 垂直专家群协同场景需要打通以下四层能力，核心差异在于每一层都需要按 Agent 数量独立配置：

| **能力层** | **钉钉能力** | **说明** |
| --- | --- | --- |
| **AI 开发套件** | 多个群机器人（每个 Agent 一个独立机器人） | 通过钉钉开放平台为每个垂直领域创建独立机器人，或通过智能体插件接入已有的 OpenClaw / Hermes Agent，统一添加到同一个群 |
| **数据接入层** | 各 Agent 按职责接入不同 API | HR Agent 使用考勤/通讯录接口，财务 Agent 使用审批/AI 表格接口，法务 Agent 使用文档/知识库接口，技术 Agent 使用文档/知识库接口 |
| **AI 能力层** | 各 Agent 订阅独立的 SkillHub | HR Agent 订阅"HR管理 SkillHub"，法务 Agent 订阅"法务合规 SkillHub"，财务 Agent 订阅"财务管理 SkillHub"——每个 Agent 拥有独立的 Skill 能力域 |
| **用户交互层** | 群聊 @触发精确路由 + 差异化 AI 卡片 | 通过 @不同 Agent 名称精确路由到对应领域，各 Agent 使用不同颜色/图标的卡片样式，便于辨识回复来源 |

以上能力中，AI 开发套件和数据接入层为必须项，SkillHub 能力扩展和差异化 AI 卡片为增强项。最小可用版本只需完成"多机器人创建 → 各自接入知识库 → 文本回复"即可上线。

> **[!IMPORTANT]**
>
> 钉钉群机器人只接收 @ 自己的消息，且机器人发出的消息不会触发其他机器人。因此 Agent 回复中出现的"@财务助手"等内容仅为文字引导，须由用户重新 @ 对应机器人才能触发它；多个 Agent 之间不会自动接力，路由完全由人驱动。

## 开放平台配置（多机器人创建）

本场景需要为每个垂直领域创建独立的机器人应用。登录 [钉钉开放平台开发者后台](https://open-dev.dingtalk.com/)，重复以下步骤完成所有 Agent 的创建。

### 步骤 1：逐一创建 OpenClaw 机器人

在**应用开发**下，点击**立即创建**，选择一键创建 OpenClaw 机器人。每个 Agent 创建一个独立机器人，建议按以下命名和图标规范配置，确保群成员能直观区分：

| **Agent** | **机器人名称** | **图标颜色建议** | **职责定位** |
| --- | --- | --- | --- |
| HR Agent | HR助手 | 绿色 | 考勤、请假、招聘政策、社保公积金 |
| 法务 Agent | 法务助手 | 蓝色 | 合同审核、合规咨询、法规检索 |
| 财务 Agent | 财务助手 | 橙色 | 报销规则、预算查询、发票管理 |
| 技术 Agent | 技术助手 | 紫色 | 技术文档、故障排查、架构规范 |

> **[!NOTE]**
>
> 机器人应用名称在企业内唯一（2~20 字），"HR助手""法务助手"这类通用名称撞名概率较高；创建报 FAIL 时请优先排查名称重复，可加部门/团队前缀（如"研发部-HR助手"）。需要批量创建时，也可以使用 CLI：`dws connect bot create`。

在创建界面填写机器人基本信息（机器人名称、简介和图标），点击**确定**即可。图标颜色的差异化设计能帮助群成员快速识别回复来自哪个领域的专家。

### 步骤 2：保存各应用凭证

每个 OpenClaw 创建成功后，页面会自动展示该应用的 `Client ID` 和 `Client Secret`。请分别保存每个 Agent 的凭证，后续各 Agent 的服务端配置和 SkillHub 接入均需独立使用各自的凭证。

### 步骤 3：将所有机器人添加到同一个群

在项目群的群设置中，依次将已创建的所有机器人添加到群中。添加完成后，群成员即可通过 @机器人名称 来精确触发对应 Agent。钉钉会根据 @的机器人名称自动将消息路由到对应的 Agent 服务端，无需额外的路由逻辑。

## 各 Agent 数据接入配置

每个 Agent 根据自身职责接入不同的钉钉能力。以下分别说明各 Agent 的数据接入方案。

### HR Agent 数据接入

HR Agent 需要接入考勤、通讯录和知识库三类数据源：

| **数据源** | **接入方式** | **核心能力** |
| --- | --- | --- |
| HR 知识库 | DWS CLI `dws wiki`（space search / node 检索）或钉钉知识库 API | 检索请假制度、考勤规则、招聘流程、员工手册等文档，构建 RAG 索引 |
| 考勤数据 | DWS CLI `dws attendance`（如 `dws attendance vacation balance` 查假期余额、`dws attendance record list` 查打卡记录） | 查询员工打卡记录、排班信息、假期余额 |
| 通讯录 | DWS CLI `dws contact`（如 `dws contact user profile` 查花名册、`dws contact user search` 搜员工） | 搜索员工信息、部门组织架构、花名册查询 |

HR 知识库建议在钉钉知识库中创建"HR政策"空间，按以下结构组织文档：考勤管理制度、各类假期说明（年假/事假/病假/婚假等）、招聘流程与面试规范、薪酬福利指引、员工入离职流程。

### 法务 Agent 数据接入

法务 Agent 以知识库检索为核心能力：

| **数据源** | **接入方式** | **核心能力** |
| --- | --- | --- |
| 法务知识库 | DWS CLI `dws wiki`（space search / node 检索）或钉钉知识库 API | 检索合同模板、法律法规、合规指引、风控标准等文档 |
| 文档管理 | DWS CLI `dws doc`（如 `dws doc search` 搜索、`dws doc read` 读取正文） | 搜索和读取合同文档、法律意见书等 |

法务知识库建议包含：标准合同模板库、常见法律风险 FAQ、行业合规政策解读、保密协议与竞业限制说明、知识产权管理规范。

### 财务 Agent 数据接入

财务 Agent 需要接入审批、AI 表格和知识库三类数据源：

| **数据源** | **接入方式** | **核心能力** |
| --- | --- | --- |
| 财务知识库 | DWS CLI `dws wiki`（space search / node 检索）或钉钉知识库 API | 检索报销标准、预算制度、发票管理规定等文档 |
| 审批数据 | DWS CLI `dws oa`（如 `dws oa approval list-pending` 查待我审批、`dws oa approval detail` 查审批详情） | 查询报销审批状态、费用申请进度 |
| 预算表格 | DWS CLI `dws aitable`（如 `dws aitable record query` 查询表格记录） | 查询项目预算余额、费用汇总等结构化数据 |

财务知识库建议包含：差旅报销标准（按城市级别分类）、费用申请流程与审批权限、发票管理规范、预算编制与调整规则、税务相关 FAQ。

### 技术 Agent 数据接入

技术 Agent 以技术文档检索和运维信息查询为核心：

| **数据源** | **接入方式** | **核心能力** |
| --- | --- | --- |
| 技术知识库 | DWS CLI `dws wiki`（space search / node 检索）或钉钉知识库 API | 检索架构设计文档、API 文档、运维手册、故障排查指南 |
| 技术文档 | DWS CLI `dws doc`（如 `dws doc search` 搜索、`dws doc read` 读取正文） | 搜索和读取技术文档、设计方案 |

技术知识库建议包含：系统架构说明、环境配置参数、常见故障排查手册、编码规范与代码评审标准、发布部署流程。

## SkillHub 能力接入

[钉钉 AI 能力中心](https://aihub.dingtalk.com/#/skill)（SkillHub）是本场景实现"垂直专家"能力的关键差异点。每个 Agent 订阅各自领域的专属 SkillHub，使其具备超越知识检索的深度专业能力。

### 接入流程

1. 使用钉钉账号登录 [钉钉 AI 能力中心](https://aihub.dingtalk.com/#/skill)；为目标 Agent 接入 Skill 时，填入该 Agent 的应用凭证完成授权（凭证用于授权，而非登录动作）。
2. 根据该 Agent 的领域定位，浏览对应分类下的 Skill，或搜索相关关键词。
3. 选择目标 Skill，点击进入详情页查看能力说明、触发词、所需权限。
4. 点击接入，按引导完成 Skill 的配置和授权，Skill 即挂载到该 Agent 上。
5. 对每个 Agent 重复上述流程，确保各 Agent 只订阅本领域的 Skill。

### 各 Agent 推荐订阅的 SkillHub

| **Agent** | **Skill 分类** | **推荐 Skill** | **能力描述** |
| --- | --- | --- | --- |
| **HR Agent** | HR管理 | salary-query（薪酬查询） | 查询员工薪酬相关信息 |
|  |  | apply-vacation（假期申请） | 按假期类型发起请假申请 |
| **法务 Agent** | 法务合规 | contract-review（智能合同审查） | 对合同文本自动识别风险条款，给出审查意见 |
| **财务 Agent** | 财务管理 | invoice-ocr-verify-skill（发票OCR验真） | 上传发票图片自动识别字段并验真 |
| **技术 Agent** | 技术运维 |  | 可在 AI 能力中心按"故障排查""监控"等关键词检索，以实际上架为准 |

> 注：上表条目以 AI 能力中心实际上架为准，Skill 名称可能随版本变化；接入前请先在能力中心实际检索确认。

每个 Agent 只订阅自己领域的 Skill，避免能力交叉导致回复混乱。SkillHub 中的 Skill 持续更新，建议定期浏览各分类下的新 Skill。

## AI 卡片交互配置

多 Agent 场景下，卡片设计的核心原则是**来源可辨识**——群成员一眼就能看出这条回复来自哪个领域的专家。

### 各 Agent 的卡片类型选型

| **卡片类型** | **适用 Agent** | **核心能力** | **推荐度** |
| --- | --- | --- | --- |
| **知识问答卡片** | 全部 Agent | Markdown 富文本展示回答内容 + 引用来源链接 + 反馈按钮，各 Agent 通用的基础卡片 | ⭐⭐⭐ 首选 |
| **数据查询卡片** | HR / 财务 | 以表格形式展示考勤记录、报销标准、预算余额等结构化数据 | ⭐⭐⭐ 推荐 |
| **风险提示卡片** | 法务 | 高亮展示风险等级（高/中/低），列出风险点和建议措施，附带操作按钮（提交审核等） | ⭐⭐⭐ 推荐 |
| **操作引导卡片** | HR / 财务 | 展示操作步骤指引，内嵌快捷操作按钮（发起审批、提交申请等） | ⭐⭐ 增强 |
| **故障排查卡片** | 技术 | 展示排查步骤、配置参数、历史案例，附带跳转按钮（监控面板、工单系统等） | ⭐⭐ 增强 |

### 卡片接入方式

钉钉 AI 卡片通过**卡片模板**进行管理。为每个 Agent 分别创建对应风格的卡片模板，在模板中设定各自的主色调和图标。开发者在钉钉开放平台的**卡片平台**中创建模板，定义布局结构和数据变量，Agent 回复消息时引用各自的模板 ID 并填充实际数据即可渲染差异化卡片。具体操作流程参考钉钉开放平台文档中"互动卡片"章节。

## 验证与测试

完成以上所有配置后，按以下步骤验证多 Agent 协同是否正常工作：

### 基础连通性测试

1. 确认所有机器人已添加到同一个测试群中。
2. 分别发送 `@HR助手 你好`、`@法务助手 你好`、`@财务助手 你好`、`@技术助手 你好`，确认每个 Agent 都能独立收到消息并回复。
3. 确认各 Agent 的回复使用了各自风格的卡片样式，来源可辨识。

### 领域准确性测试

验证每个 Agent 只回答自己领域的问题，不越界回复：

| **测试指令** | **预期行为** |
| --- | --- |
| "@HR助手 年假还剩几天" | HR Agent 查询假期余额并回复 |
| "@法务助手 保密协议一般签几年" | 法务 Agent 检索法务知识库并回复 |
| "@财务助手 出差深圳住宿费报销上限是多少" | 财务 Agent 返回报销标准数据表 |
| "@技术助手 生产环境数据库的连接池配置是什么" | 技术 Agent 检索技术文档并回复 |

### 路由隔离测试

验证 @路由机制的准确性——向一个 Agent 提问其他领域的问题，Agent 应当礼貌引导用户 @正确的 Agent：

| **测试指令** | **预期行为** |
| --- | --- |
| "@HR助手 报销标准是多少" | HR Agent 回复"报销相关问题建议 @财务助手 咨询" |
| "@技术助手 请假流程是什么" | 技术 Agent 回复"请假相关问题建议 @HR助手 咨询" |
