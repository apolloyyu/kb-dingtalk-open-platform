# 5分钟配置：给自己配个嘴替AI 机器人

## 为什么要用它

### **方案定位**

为钉钉群打造一个"会读文档的 AI 问答机器人"。它能自动读懂你的钉钉文档，在群里有人提问时精准给出答案；而且只在问题跟文档相关时才去读文档，平时正常聊天不扰民，不会把每一句话都当成"查文档"任务处理。

### **适用场景**

- **重复问答太累人**： 群里总有人反复问同一个问题，每次都要翻文档、截图、解释半天，心累又耗时。
- **新人上手成本高**： 新同事入职，要把一堆文档链接发过去，还担心他们找不到重点、看不明白。
- **知识沉淀没出口**： 团队积累了大量文档，但没人愿意一条条去翻，知识躺在文档里睡大觉。
- **想要自动化助手**： 希望有个机器人能自动读懂文档，精准回答问题，平时正常聊天不扰民。

### **核心优势**

- **零代码门槛**： 不需要写代码，只需要配置几个工具，剩下的交给机器人。
- **5分钟快速搭建**： 从安装到测试，一杯咖啡的时间就能搞定。
- **智能判断不扰民**： 机器人会先判断问题是否跟文档相关，相关才去读文档，不相关就正常聊天。
- **一次配置永久生效**： 把"重复了 100 遍的人工动作"变成自动化流程，解放你的时间。

**机器人几秒后回复（内容是从文档里总结出来的）**：

## **先搞懂：它们是什么**

动手前花 3 分钟理解几个概念，后面操作会更顺畅。

### 什么是 Agent 端

你可以把它理解成一个"会执行任务的 AI 助手客户端"：在这里跟 AI 对话，它不仅能聊天，还能帮你执行命令、操作文件、调用各种工具（比如本文用到的"千问办公"）。**它不是网页版的聊天框，而是一个能"真正干活"的助手**。

### 什么是钉钉机器人

就是钉钉群里那个可以被 @ 的"机器人账号"：它本身不聪明，只是"收发消息的身份"，有人 @ 它，消息就被推送出去；有人告诉它该说什么，它就在群里说出来。**真正的"脑子"不在机器人身上，而是在 Agent 端**。

> **[!NOTE]**
>
> 更多机器人介绍，可查看[机器人概述](../01-XOnnmGCTbn-开发指南/0075-robot-application-overview.md)。

### **两者如何配合**

简单说就是"钉钉负责收发消息，Agent 端负责思考"：

```
群友 @机器人 发消息
      │
钉钉服务器把消息推给"钉钉频道连接器"（相当于一根打通两边的管道）
      │
消息被路由到 Agent 端里专门处理这个群的"群聊 IM 实例"
      │
Agent 端判断：这个问题跟文档相关吗？
      │
      ├─ 相关 → 读文档 → 总结 → 生成回复
      └─ 不相关 → 直接正常聊天回复
      │
回复通过同一条管道，以"机器人"的身份发回钉钉群
```

### 机器人如何"读文档"

靠一个叫 **DWS（DingTalk Workspace）CLI**的命令行工具：你可以把它理解成"钉钉文档的遥控器"，Agent 端不需要打开浏览器登录钉钉，只需执行一条命令（比如 `dws doc read --node <文档链接>`），就能拿到文档的完整内容。

### 什么是 Skill

Skill 是给 Agent 端"立的规矩"：用自然语言写成的说明书，告诉它"以后看到跟 XX 主题相关的问题，要做 1、2、3、4 这几件事"。本文要创建的 Skill 叫 `dingtalk-doc-qa`，规矩是"群里有人问跟文档相关的问题，就去读文档、总结、回复，不相关就正常聊"。

理解了这 5 点，下面的操作步骤你就能看懂每一步在干什么，而不是机械抄命令。

## **开始前，确认 4 件事**

| 需要什么 | 说明 |
| --- | --- |
| 一个 Agent 端 | 本文以千问办公为例。 |
| 一个有创建机器人权限的钉钉账号 | 组织管理员或开发者账号。 |
| 一份你钉钉文档承载知识 | 提前建好，且这个账号有阅读权限。 |
| 钉钉DWS CLI（≥ 1.0.15） | 命令行工具，装一次就行：`npm install -g dingtalk-workspace-cli` |

如果你用的是自部署 Agent（比如 OpenClaw），还需要先装好 OpenClaw（≥ 2026.4.9），再装 `openclaw-connector` 插件，后面 Step 1 会讲到。

## 跟着做，搭出同款嘴替机器人

本文以"千问办公"作为 Agent 端示例。其他支持 IM 消息接收、CLI 执行、Prompt 控制的 Agent 端（比如自部署的 OpenClaw），核心步骤完全一样，只是打通消息通道的方式略有不同。

### Step 1：打通钉钉消息通道

这一步把"钉钉"和"Agent 端"连起来，实现消息双向流通。

**不同 Agent 端的接入方式**：

| **Agent 端类型** | **钉钉消息接入方式** | **说明** |
| --- | --- | --- |
| 千问办公（本案例） | 内置钉钉频道连接器 | OAuth 授权后自动接收消息，低配置。 |
| 自部署 Agent（如OpenClaw） | [dingtalk-openclaw-connector](https://github.com/DingTalk-Real-AI/dingtalk-openclaw-connector) 插件 | 钉钉官方开源插件，扫码授权一键打通，支持群聊/单聊消息收发、文档操作等。 |
| 其他 Agent 平台 | 自建 Webhook / 钉钉开放平台 API | 需自行实现消息接收与路由。 |

对于千问办公，直接在连接器板块安装好钉钉即可。

![image.png](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/9913806871/p1093832.png)

### Step 2：确认 DWS 登录组织

这一步容易被忽略，但踩坑率极高：**DWS 连接的组织决定了它能读到哪些文档**，如果文档在 A 组织，DWS 却登录在 B 组织，读文档时会直接报"跨组织访问错误"。

跑一下这条命令确认：

```
dws contact me --format json
```

返回结果包含当前登录的组织名称、corpId、用户信息，核对是否与你文档所在组织一致。

### Step 3：添加钉钉机器人

**千问办公**： 在频道设置页面找到钉钉频道的机器人配置项，按引导操作即可创建。

> **[!IMPORTANT]**
>
> 在添加钉钉机器人前，需要具备该组织的开发者权限，如何添加请参见[获取开发者权限](../01-XOnnmGCTbn-开发指南/0006-get-developer-permissions.md)说明。

![image](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/9913806871/p1093838.png)

### Step 4：把机器人拉进钉钉群

回到钉钉客户端操作：

1. 打开或新建一个群。
2. 群设置 → 群机器人 → 添加。
3. 选中刚创建的机器人并加入。

机器人进群后，Agent 端会自动感知到这个新的群会话，无需手动配置，机器人如何添加入群，可参考[添加机器人入群](../01-XOnnmGCTbn-开发指南/0077-add-robot-to-group.md)介绍。

### Step 5：验证消息通道

先在钉钉群里 @ 机器人，随便发句"你好"，然后回到 Agent 端客户端问它："帮我看看钉钉群有没有收到消息"。

Agent 会查询已连接的 IM 会话，找到你刚发的消息和机器人的自动回复，如果能看到，说明消息通道已彻底打通。

### Step 6：创建文档问答 Skill

> **[!NOTE]**
>
> 千问办公使用 SKILL.md 控制 Agent 行为。其他 Agent 端可替换为等价的 Prompt 模板/系统指令/工作流配置。核心逻辑一致：定义触发条件 → 判断相关性 → 调用 DWS 读文档 → 总结回复。

消息通道验证通过后，创建一个 skill，让 Agent 在收到文档相关问题时自动读取钉钉文档并总结回复。

1. 获取文档信息并验证可读取。

   ```
   dws doc info --node "<你的钉钉文档链接>" --format json
   dws doc read --node "<你的钉钉文档链接>" --format json
   ```

   > **[!NOTE]**
   >
   > **跨组织问题**：如果钉钉文档 MCP 连接的组织与文档所属组织不同，会报 `forbidden.accessDenied`。改用 dws CLI 的 `doc read` 读取即可，只要 DWS 连接的组织与文档所属组织一致。
2. 在千问办公客户端对话中输入创建 Skill 内容：

   ```
   帮我创建一个 skill，名字叫 dingtalk-doc-qa。
   功能：在钉钉群/单聊@机器人时，如果问题跟 <文档主题> 相关，就读取钉钉文档并总结回答；不相关的问题正常回答。
   文档链接：<你的钉钉文档链接>
   ```

   Skill 内容应包含：

   - **触发条件**： 用户消息包含与文档主题相关的关键词。
   - **判断逻辑**： 先判断是否相关，相关才读取文档。
   - **执行步骤**： DWS `doc read` 读取文档 → 定位相关段落 → 总结回复。
   - **降级方案**： DWS 执行失败时告知用户并给出文档链接。
3. 输入下方内容，验证安装，确认 skill 出现在可用列表中。

   ```
   帮我看一下 dingtalk-doc-qa skill 是否安装好了
   ```

### Step 7：真人测试完整流程

在钉钉群里 @ 机器人，问一个文档里确实提到的问题；等它处理完后，可以查看执行记录。

![image](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/9913806871/p1093839.png)

## 方案不挑人，换个马甲照样灵

本文用千问办公做示例，但只要一个 Agent 端满足这三个条件，都能照搬这套方案：

1. 能接收钉钉 IM 消息。
2. 能执行 CLI 命令或调用 MCP 工具。
3. 能通过 Prompt / 指令文件控制自己的行为。

不同 Agent 端接入钉钉消息的方式不太一样：

| **Agent 端类型** | **钉钉消息接入方式** | **说明** |
| --- | --- | --- |
| 千问办公（本案例） | 内置钉钉频道连接器 | OAuth 授权后自动接收消息，低配置最省心。 |
| 自部署 Agent（如OpenClaw） | [dingtalk-openclaw-connector](https://github.com/DingTalk-Real-AI/dingtalk-openclaw-connector) 插件 | 钉钉官方开源插件，扫码授权一键打通，支持群聊/单聊消息收发、文档操作等。 |
| 其他 Agent 平台 | 自建 Webhook / 钉钉开放平台 API | 需自行实现消息接收与路由。 |

无论用哪种方式，核心链路都是一句话："**钉钉负责收发消息，Agent 端负责判断相关性、读文档、总结回复**"。
