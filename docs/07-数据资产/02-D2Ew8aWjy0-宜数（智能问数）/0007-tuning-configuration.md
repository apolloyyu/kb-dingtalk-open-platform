# 调优配置

> **[!NOTE]**
>
> **高级版**可使用。

## **概述**

在数据管理配置的基础下，如果进一步优化问数的效果，需要调优配置主动去干预。这里的效果主要指几个方面：

- 准确率：查询的数据不符合预期，例如问的是销售额，计算是销售量；又例如一些行业黑话，模型无法理解；对于一些特别复杂的问题，通常是包含特定计算逻辑的查询，模型可能无法稳定输出预期的结果
- 图表展示：查询的数据，没有按期望的形式展示，例如希望展示为柱状图，但是展示成了折线图；又例如希望金额展示为万元，原始数据里面金额的单位是分。

目前包含以下几种调优能力：

| **能力** | **说明** |
| --- | --- |
| 同义词 | 同样含义的词汇，例如 “进货” = “采购”，“资产” = “库存” 等，不同词汇代表同样的含义。 |
| 专业名词 | 专业的名词解释、行业黑话等，例如进销存，成交均价，需要对此类名词做进一步的解释。 |
| 业务逻辑 | 特定的业务口径解释，例如 “销售情况 = 销售量 + 销售额”，“排行 = 取前10名” 等。 |
| 样例库 | `问题描述 + 正确SQL`的样例，基于 few shots 机制，让模型模仿解决一类问题。 |
| 表选择 | 通过关键词，表选择逻辑，表选择示例来定义一系列表选择的规则，大模型会结合用户的问题根据设定的规则精确的匹配数据表。 |
| SQL模板 | 通过`问题内容 + SQL模板 + 模板变量`，更加精准地控制模型的输出，适合逻辑特别复杂的查询情况，也可以作为兜底措施 |

## **功能价值**

数据管理配置中，清晰的数据集和表结构的名称、描述可以让模型实现基础的问数效果，使用配置调优，让模型发挥更大的潜力，进一步提升问数的准确率的展示效果。

## **能力边界**

- 调优的前提是清晰的表结构，在数据管理配置阶段，对表名称、描述、字段的清晰定义，是后续调优的基础。
- 避免将琐碎的数据预处理逻辑配置成同义词，这一步应该在前置数据管理阶段完成。例如，某商品，在数据库中有多种不规范的名称，用户尝试在同义词中配置映射，实际却不生效，这种问题更适合在前置的数据预处理阶段完成。
- 简单的计算逻辑适或行业黑话合配置在专有名词，例如：

  - 成交均价=销售金额 ÷ 销售量；
  - 孖单 = 同一客户在一段时间内下的相同商品的订单。
- 业务逻辑适合描述宽泛的领域知识或输出限制，例如：

  - 签约包含签约金额、签约数量两个指标。
  - 今年以来是指从今年的1月到当前月。
  - 金额，默认以万元为单位，显示两位小数符。
- 避免在业务逻辑中描述过于复杂的计算逻辑，例如涉及到多层嵌套的查询，这种查询很难用一句话描述准确，更适合在样例库或SQL模板中配置。
- 样例库的核心逻辑是模仿，模型可能只会模仿样例，而无法应对样例覆盖之外的变种问题。样例需要具有一定的泛化性，太过具体的 SQL 可能会导致模型生成的 SQL 缺乏灵活性，例如 SQL 中使用具体的日期区间，不如使用时间函数更加通用。样例的配置，一般以 MySQL 语法为准。

## 场景一：配置同义词理解业务术语

### **使用效果**

| **Before** | **After** |
| --- | --- |
| 无法理解什么是资产 ❌  image | 正确的理解了资产代表库存 ✅  image |

### **配置流程**

1. 配置[数据源](0005-data-management-configuration.md)，进入智能问数配置页面。
2. 单击**调优配置** > **同义词** > **添加同义词**，并进行配置：

   | **配置项** | **说明** |
   | --- | --- |
   | 词语 | 填写：资产。 |
   | 同义词 | 填写：采购。  同义词支持多个，回车后可输入下一个，录入完成后点击确认。 |

   配置完成后，单击**确认**。
3. 同义词配置完成后，你可以在预览调试台，再次测试验证效果。

## **场景二：**配置专业词理解业务术语

### **使用效果**

| **Before** | **After** |
| --- | --- |
| 无法理解长尾商品的含义 ❌image   ``` SELECT `sku` AS 库存单位编号, `classify` AS 分类, `series` AS 系列, SUM(`sale_total`) AS 总销售额   FROM sales   GROUP BY `库存单位编号`, `分类`, `系列`   HAVING SUM(`sale_total`) < (   SELECT AVG(`sale_total`)   FROM sales   )   ORDER BY 总销售额 ASC ``` | 理解了长尾商品的含义 ✅  image.png   ``` SELECT `sku` AS 库存单位编号, `brand` AS 品牌, `classify` AS 分类, `series` AS 系列   , SUM(CASE    WHEN `record_date` >= DATE_SUB(CURDATE(), INTERVAL 90 DAY) THEN `sale_total`   ELSE 0   END) / SUM(`sale_total`) * 100 AS 销量占比   FROM sales   WHERE `record_date` <= CURDATE()   GROUP BY `sku`, `brand`, `classify`, `series`   HAVING 销量占比 < 5 ``` |

### **配置流程**

1. 配置[数据源](0005-data-management-configuration.md)，进入智能问数配置页面。
2. 单击**调优配置** > **专业名词** > **添加专业名词**，并进行配置：

   | **配置项** | **说明** |
   | --- | --- |
   | 专业名词 | 填写：长尾商品。 |
   | 专业名词解释 | 填写：过去90天销售占总销售比例不足5%的商品。  同义词支持多个，回车后可输入下一个，录入完成后点击确认。 |

   添加完成后，单击保存。
3. 专业名词配置完成后，你可以在预览调试台，再次测试验证效果。

## 场景三：配置业务逻辑理解提问习惯

### **使用效果**

| **Before** | **After** |
| --- | --- |
| 销售排行希望默认输出前 3 名，但是输出太多内容。 ❌image | 理解了业务逻辑，只输出了销售额前三名 ✅  image |

### **配置流程**

1. 配置[数据源](0005-data-management-configuration.md)，进入智能问数配置页面。
2. 单击**调优配置** > **业务逻辑** > **添加业务逻辑**，并进行配置：

   > **[!NOTE]**
   >
   > 1. 一般是 条件 + 执行的表达方式，例如，当查询 xxx 的时候，输出 xxx。
   > 2. 可以适当技术化描述，效果更好，例如，将销售额按照降序排列。
   > 3. 业务逻辑之间不要互斥，例如：业务逻辑A希望查询销售排行的时候按照销售额排序，业务逻辑B希望按照销售量排序。

   | **配置项** | **说明** |
   | --- | --- |
   | 业务逻辑解释 | 填写：分品类计算销售排行，将销售额按倒序排列，输出前三名。 |

   添加完成后，单击**保存**。
3. 业务逻辑配置完成后，你可以在预览调试台，再次测试验证效果。

## 场景四：配置样例库锁定标准答案

### **使用效果**

| **Before** | **After** |
| --- | --- |
| 库存周转率无法正确输出。 ❌  image | 参考样例正确输出了结果 ✅  image |

### **配置流程**

1. 配置[数据源](0005-data-management-configuration.md)，进入智能问数配置页面。
2. 单击**调优配置** > **样例库** > **添加样例**，并进行配置。

   > **[!NOTE]**
   >
   > 1. 对于智能问数托管的数据集，如通过 Excel 上传的数据集、多维表，可以通过右侧组件选择到数据表对应的表名。
   > 2. 样例库中配置的 SQL，一定要保证可执行性，否则模型可能会错误理解，模仿错误的示范
   > 3. 配置的 SQL，尽量简洁，避免使用复杂的 JOIN 查询，大批量的拉取数据查询（如 select ... limit 10000）。

   | **配置项** | **说明** |
   | --- | --- |
   | 问题内容 | 填写期望的示例问题。 |
   | 预期正确执行的 SQL | 填写预期执行的 SQL 语句。  image |

   添加完成后，单击**保存**。
3. 样例库配置完成后，你可以在预览调试台，再次测试验证效果。

## **场景五：**配置SQL模板统一相似问题结果

### **使用效果**

| **Before** | **After** |
| --- | --- |
| 高销量SKU模型理解为销量超过平均水平，不符合预期 ❌image | 直接命中SQL模板，按照模板直接查询 ✅  image |

### **配置流程**

1. 配置[数据源](0005-data-management-configuration.md)，进入智能问数配置页面。
2. 单击**调优配置** > **SQL 模板** > **添加模板**，并进行配置：

   | **配置项** | **说明** |
   | --- | --- |
   | 模板名称 | 填写预期模板名称，例如：分析高销量SKU的库存状态。 |
   | 模板描述 | 填写预期模板描述，例如：高销量SKU代表销量前10的SKU。 |
   | 问题内容 | 填写问题内容，例如：  - 分析高销量SKU的库存状态 - 高销量的SKU库存情况怎么样？ |
   | 模板回复 | 填写对应的 SQL，例如：   ``` SELECT ts.sku, ts.total_sales, st.stock_total, st.stock_quantity FROM (SELECT sku, SUM(sale_total) AS total_sales FROM sales WHERE record_date BETWEEN '${start_datey}' AND '${end_date}' GROUP BY sku ``` |
   | 变量描述 | 填写变量解释信息，例如：  - start\_date：开始时间 - end\_date：结束时间 image |

   添加完成后，单击**保存**。
3. SQL 模板配置完成后，你可以在预览调试台，再次测试验证效果。

## 场景六：配置表选择解决多表路由

### **使用效果**

| **Before** | **After** |
| --- | --- |
| 查询滞销的商品，路由到了销售表，希望路由到库存表 ❌image | 配置表路由后，路由到了库存表 ✅  image |

### **配置流程**

1. 配置[数据源](0005-data-management-configuration.md)，进入智能问数配置页面。
2. 单击**调优配置** > **表选择**，并进行配置：

   > **[!NOTE]**
   >
   > 如果同一个关键词，希望路由到多个数据表，可以分别在每个数据表的关键词中配置。

   | **配置项** | **说明** |
   | --- | --- |
   | 模型选择 | 选择预期模型。 |
   | 默认数据表 | 选择一张数据表作为默认数据表。 |
   | 数据表关键词 | 对数据表配置关键词，例如，对库存明细表设置了滞销。  image |
   | 表选择逻辑（可选） | 可以配置表选择逻辑，表选择逻辑类似于业务逻辑，用一句话表达。 |
   | 表选择示例 | 可以进一步配置表选择示例，示例输入匹配用户输入的问题，示例输出是对应的数据表（支持多选）。  image |

   添加完成后，单击**保存**。
3. 表选择配置完成后，你可以在预览调试台，再次测试验证效果。
