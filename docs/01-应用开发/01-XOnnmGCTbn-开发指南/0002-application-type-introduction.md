# 应用类型与能力说明

本文档整合了钉钉开放平台官方说明，帮助开发者快速了解应用分类体系、核心能力形态及选型策略。

## 快速概览

钉钉开放平台的应用体系由四个应用类型和四种应用能力组成，开发者可先根据服务对象和商业化需求确定应用类型，再根据业务场景选择合适的技术能力。

| **应用类型** | **小程序** | **网页应用** | **酷应用** | **机器人** |
| --- | --- | --- | --- | --- |
| **企业内部应用** | ✅ | ✅ | ✅ | ✅ |
| **第三方企业应用** | ✅ | ✅ | ✅ | ✅ |
| **第三方个人应用** | ✅ | ❌ | ❌ | ❌ |
| **移动应用接入** | ❌ | ❌ | ❌ | ❌ |

## 应用类型详解

| **应用类型** | **定位** | **适用场景** | **核心特征** | **支持能力** |
| --- | --- | --- | --- | --- |
| **企业内部应用** | 仅供单一企业内部使用的私有化定制应用，无需上架审核 | 内部审批工具、业务管理系统、解决企业特定痛点的定制化应用 | - 封闭垂直，不上架应用广场，无需审核 - 由企业内部开发者或委托服务商开发 - 员工在工作台的“全部应用”中可见  **[!NOTE]**  需管理员手动添加到工作台首页才能置顶展示   image | - 小程序 - 网页应用 - 酷应用 - 机器人 |
| **第三方企业应用** | 面向多个企业客户的 SaaS 化服务应用，必须上架应用广场并通过审核 | 软件服务商（ISV）开发的通用软件，如 CRM、ERP、标准化 | - 必须上架应用广场，需通过上架审核  **[!NOTE]**  上架流程严格，需参考《[合作全流程指引](../07-TjCzIgfQs3-平台服务/0027-isv-cooperation-guide.md)》 - 由产品方案商（ISV）开发 - 用户通过应用广场搜索、试用、购买，安装后出现在企业工作台中  image | - 小程序 - 网页应用 - 酷应用 - 机器人 |
| **第三方个人应用** | 服务钉钉个人用户的 C 端工具应用，独立于企业组织架构 | 不依赖企业组织的个人效率工具（记账、笔记）、生活服务类小程序 | - 不上架广场，基于个人账号体系 - 直接服务个人用户，不依赖企业组织 | - 小程序 |
| **移动应用接入** | 身份认证与分享集成，非钉钉原生应用 | 现有 App 集成钉钉登录功能、内容分享到钉钉会话。 | - 轻量级集成，仅支持登录（钉钉扫码/账号登录）和分享（分享到钉钉） | - 无（仅登录和分享能力） |

## 应用能力详解

### 小程序

- **定义**：运行在钉钉客户端内的轻量级应用，具备接近原生应用的性能体验。
- **适用场景**：协同办公、人力资源管理、审批流程、客户关系管理等企业服务场景。
- **技术特点**：

  - 跨端统一：一次开发即可在 iOS、Android、Windows、Mac 多端运行
  - 高性能渲染：页面切换流畅，响应迅速
  - 离线可用：支持资源本地缓存，弱网或断网环境下仍能访问部分内容
  - 丰富 JSAPI：支持扫码、地理位置、音视频播放等设备能力

- **开发支持**：专属钉钉开发者工具（项目创建、模拟器预览、真机调试）、统一的 UI 组件库。

### 网页应用（H5 微应用）

- **定义**：基于标准 Web 技术开发的应用形式，通过浏览器内核在钉钉中运行。
- **适用场景**：快速上线、轻量级功能集成、已有 Web 系统迁移。
- **主要特点**：

  - 开发门槛低：可复用现有 Web 工程技术栈（Vue、React 等），快速迁移已有系统
  - 灵活集成：适用于单页面或多页面结构，易于与外部系统对接
  - 强大 JSAPI：可调用设备能力及钉钉特有功能（分享、钉盘上传、联系人选择器）
- **小程序 vs 网页应用**

  | **对比项** | **小程序** | **H5 微应用** |
  | --- | --- | --- |
  | 加载性能 | 首次略慢，后续快（本地缓存） | 受网络环境影响大 |
  | 使用性能 | 流畅顺滑，接近 Native 体验 | 复杂场景可能卡顿 |
  | 开源 UI 组件 | 不支持 | 支持任意 Web UI 框架 |
  | 灰度发布 | 平台原生支持 | 需自行实现 |
  | CDN 服务 | 默认提供 | 需自行配置 |
  | 开发个人应用 | 支持 | 不支持 |
- **选型建议**：优先选择小程序，除非是简单的网页嵌入需求或需复用现有 Web 框架。
- **注意事项**：页面加载性能受网络影响较大，建议对静态资源进行压缩与缓存优化；需自行实现灰度发布策略和 CDN 配置。

### 酷应用

- **定义**：以"卡片 + 交互"为核心的新型应用形态，专为提升群聊、文档、音视频会议等协作场景中的信息透出效率而设计。
- **核心理念**：将传统应用的功能解构为动态卡片，在用户沟通过程中实时呈现关键数据与操作入口。
- **典型应用场景**：

  - 群内任务协作：展示待办任务列表，支持点击完成
  - 审批流程推进：发送审批请求卡片，收件人可在聊天中直接处理
  - 订单状态同步：订单更新后自动推送状态卡片
  - 会议议程互动：在音视频会议中插入议题卡片，参会者可投票或填写反馈
- **核心特性**：浅透出设计（减少上下文切换）、强交互能力（按钮点击、表单提交、状态更新）、事件驱动更新（自动刷新卡片内容）。

### 机器人

- **定义**：一项独立的应用能力，可用于开箱即用的消息通知，也可通过二次开发实现智能化协作流程。
- **核心价值**：无需绑定特定应用或群组即可快速部署，将业务系统的事件主动推送到钉钉群聊或个人会话中。
- **主要类型**：

  - 自定义机器人：通过 Webhook 地址向指定群发送消息，支持文本、富文本、Markdown、卡片等多种格式
  - 群助手机器人：具备接收消息与响应能力，可实现问答、菜单选择、表单收集等交互逻辑
- **典型用途**：系统告警通知、每日日报汇总、审批提醒、任务分配与追踪。

## 选型指南

### 应用类型选择

| 考量维度 | 选择建议 |
| --- | --- |
| 服务对象 | - 企业内部使用 → 企业内部应用 - 面向多企业 → 第三方企业应用 - 个人用户 → 第三方个人应用 |
| 商业化需求 | - 需要上架销售 → 第三方企业应用（需审核） - 仅内部使用 → 企业内部应用（无需审核） |
| 技术形态需求 | - 多种能力组合 → 企业内部应用或第三方企业应用 - 仅需小程序 → 三种类型均可 |

### 应用能力选择

| 需求场景 | 推荐选择 |
| --- | --- |
| 需要与用户在聊天中交互，自动发送/响应消息 | 机器人 |
| 已有 H5 技术框架，希望快速迁移到钉钉 | 网页应用 |
| 应用频繁更新内容，偏向运营类内容 | 网页应用 |
| 需要将云文档协作与企业工作流打通 | 酷应用 |
| 追求最佳用户体验，需要接近原生的性能 | 小程序 |

### 常见组合搭配

- **网页应用 + 机器人**：配合事件订阅，把 H5 应用中触发的业务通知发送到钉钉会话或群聊；
- **机器人 + 卡片消息**：进行通知下发或让用户与应用进行轻量交互；
- **小程序 + 酷应用**：在主应用外提供群聊协作场景的快速入口。

## 常见问题

- **Q1：我的应用开发好了，员工为什么找不到？**

  新创建的应用默认处于"全部应用"列表中，不会自动出现在工作台首页。需管理员进入工作台管理后台，将应用"添加到工作台"。
- **Q2：我想做 SaaS 产品，但不想走审核流程行不行？**

  不行。所有面向多企业分发的第三方应用，必须通过上架审核以确保安全性和稳定性。如不想审核，只能作为"内部应用"通过"代开发"模式由客户手动安装（管理成本高，不推荐）。
