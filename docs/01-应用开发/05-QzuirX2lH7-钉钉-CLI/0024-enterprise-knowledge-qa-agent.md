# 企业知识问答 Agent

## **场景介绍**

企业内部的制度文档、产品文档、操作手册往往散落在各个知识库和文件夹中，新员工不知道去哪里找，老员工也记不清具体条款，一个简单的问题常常要翻半天文档才能找到答案。知识问答 Agent 正是为了解决这个痛点而设计的——在钉钉内部群（如"公司制度咨询群""产品 FAQ 群"）中部署 Agent，员工只需在群内 @Agent 用自然语言提问，Agent 即可实时检索钉钉知识库中的相关文档，结合大模型的理解与总结能力，以清晰的自然语言回答问题并附带原文链接供核实。如果启用了问答日志功能，Agent 还会将高频问题记录到 AI 表格中，帮助管理员识别知识盲区并针对性地补充文档。

## **适用场景**

本方案的核心架构是"群内 @Agent 提问 → 检索知识库 → 大模型生成回答 → 结构化回复"，除企业知识问答外，以下场景也可以复用同一套架构，只需替换知识库数据源和调整 Prompt 策略即可快速落地：

![image.png](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/6613051871/p1081492.png)

| **场景** | **知识库内容** | **典型问题示例** |
| --- | --- | --- |
| IT 运维答疑 | 系统操作手册、故障排查指南、FAQ | "VPN 连不上怎么办？""怎么申请服务器权限？" |
| 销售话术支持 | 产品介绍、竞品对比、报价策略 | "客户问我们和 XX 产品有什么区别怎么回答？" |
| 法务合规咨询 | 合同模板、法律法规、合规指引 | "这种情况需要签保密协议吗？" |
| 客服内部辅助 | 客服 SOP、退换货政策、常见投诉处理 | "客户要求七天无理由退货但已拆封，怎么处理？" |
| 新人入职引导 | 入职流程、考勤制度、福利政策、系统账号申请 | "试用期多长？""怎么申请调休？" |

## 钉钉集成能力

要让知识问答 Agent 在钉钉群中正常运行，需要打通以下三层能力：

| **能力层** | **钉钉能力** | **说明** |
| --- | --- | --- |
| **AI 开发套件** | 群机器人 + 智能体插件 | 通过钉钉开放平台一键创建群机器人，或通过智能体插件将已有 OpenClaw / Hermes Agent 连接到钉钉群 |
| **数据接入层** | 钉钉知识库 API + AI 表格（可选） | 通过知识库 API 拉取全量文档内容构建 RAG 索引；可选使用 AI 表格记录问答日志 |
| **用户交互层** | AI 卡片 | 通过 AI 卡片展示结构化回答、原文链接、反馈按钮等定制交互 |

以上能力中，AI 开发套件与数据接入层的知识库部分为必须项，AI 表格日志记录和 AI 卡片交互为可选增强项。最小可用版本只需完成"接收问题 → 检索知识 → 生成回答 → 文本回复"即可上线。

## 开放平台配置

无论你使用 OpenClaw、Hermes 还是其他 Agent 平台，本节的 4 个步骤完全一致。登录 [钉钉开放平台](https://open-dev.dingtalk.com/)，找到你的应用，依次完成以下配置。

### 步骤 1：创建应用并开启机器人能力

登录钉钉开放平台，进入**应用开发** → **创建应用**，填写应用名称（如"知识问答助手"）和描述。创建完成后，在左侧导航栏进入**添加能力** → 勾选**机器人**，保存。此时系统会为你的应用分配 `Client ID`（AppKey）和 `Client Secret`（AppSecret），请妥善保管。

### 步骤 2：了解消息接收机制

机器人被 @ 的消息不通过**事件与回调**页面的事件订阅获取，无需在该页面搜索添加任何事件。用户在群内 @机器人发送的消息，会通过 Stream 回调 topic `/v1.0/im/bot/messages/get` 推送给你的服务端，这是整个问答链路的入口；接收方式在机器人能力配置与下一步的**消息接收模式**中设置。

### 步骤 3：配置消息接收模式

在**事件与回调** → **回调配置**中，选择消息接收模式。推荐使用以下两种方式之一：

| **模式** | **适用场景** | **说明** |
| --- | --- | --- |
| **Stream 模式（推荐）** | 本地开发、Agent 框架集成 | 基于长连接，无需公网 IP 和域名，开箱即用 |
| **HTTP 回调模式** | 已有公网服务的企业 | 需要配置回调 URL，钉钉将事件推送到你的服务端 |

⚠️ 如果你使用 OpenClaw 或 Hermes 等 Agent 框架，**必须选择 Stream 模式**，这些框架不支持 HTTP 回调。

### 步骤 4：添加权限并发布

进入**权限管理**页面，搜索并添加以下权限。权限码以开发者后台「权限管理」页实搜结果为准：

| **权限名称** | **权限码** | **用途** |
| --- | --- | --- |
| 企业内机器人发送消息 | `qyapi_robot_sendmsg` | Agent 向群内回复消息 |
| 知识库文档读取 | 以「权限管理」页实搜为准 | 检索并读取知识库内容 |
| AI 表格读写（可选） | 以「权限管理」页实搜为准 | 记录问答日志到 AI 表格 |

权限配置完成后，点击**版本管理与发布** → **创建版本** → **发布**。如果组织开启了应用审核，需等待管理员审批通过。

## Agent 服务端配置

完成开放平台配置后，根据你的技术选型继续配置 Agent 后端。

### 方案 A：OpenClaw 接入

**前置条件：** 已安装 OpenClaw 并完成基础配置。

1. **添加钉钉通道**

   在 OpenClaw 中通过引导式向导添加钉钉通道，使 Agent 具备操作钉钉的能力（如需安装插件，可用 `openclaw plugins install <插件名>`）：

   ```
   openclaw channels add
   ```
2. **配置钉钉连接**

   在 OpenClaw 的配置文件 `~/.openclaw/openclaw.json` 中添加钉钉通道：

   ```
   {
     "channels": {
       "dingtalk-connector": {
         "enabled": true,
         "clientId": "你的 Client ID",
         "clientSecret": "你的 Client Secret"
       }
     }
   }
   ```
3. **重启服务**

   ```
   openclaw gateway restart
   ```

### 方案 B：Hermes Agent 接入

**前置条件：** 已完成 Hermes 的钉钉 Channel 集成。如尚未完成，请先参考 [Hermes 钉钉通道配置文档](https://github.com/NousResearch/hermes-agent)。

1. **确认环境变量**

   打开 `~/.hermes/.env`，确认以下字段正确：

   ```
   DINGTALK_CLIENT_ID=your_client_id           # 开放平台的 Client ID
   DINGTALK_CLIENT_SECRET=your_client_secret   # 对应的 Client Secret
   ```

   钉钉通道默认即为 Stream 长连接模式，无需配置连接模式变量。
2. **配置知识库检索工具**

   在 Hermes 的工具链配置中注册知识库检索能力，使 Agent 能够通过钉钉知识库 API 检索文档内容。确认 Agent 可正常访问 `GET /v1.0/wiki/spaces` 与 `/v1.0/wiki/nodes` 系列等接口。
3. **重启 Hermes**

   ```
   hermes gateway restart
   ```

### 方案 C：第三方 Agent 平台接入（百炼等）

如果你使用阿里云百炼等平台搭建 Agent，需要：

1. 在平台侧创建 Agent 应用并配置大模型。
2. 将钉钉群机器人作为"渠道"接入。具体操作参考各平台文档中"钉钉接入"章节。
3. 在平台侧配置知识库——将钉钉知识库文档导出后上传至平台的 RAG 模块，或通过 API 对接实现实时检索。

## 知识库数据准备

知识库的数据质量直接决定 Agent 的回答准确率。本步骤与 Agent 服务端配置互相独立，可并行执行。

### 整理知识库结构

在钉钉知识库中，建议按以下结构组织文档：

```
企业知识库（Space）
├── 公司制度
│   ├── 考勤管理制度
│   ├── 请假审批流程
│   └── 报销标准与流程
├── 产品文档
│   ├── 产品 A 使用手册
│   ├── 产品 B FAQ
│   └── 版本更新日志
└── 操作手册
    ├── OA 系统操作指南
    ├── CRM 使用教程
    └── 新员工入职指引
```

### 构建 RAG 索引

通过钉钉开放平台知识库 API 批量拉取文档内容，构建 RAG 检索索引。知识库的数据访问分为两层：空间管理 API 负责获取知识库列表，文档 API 负责搜索和读取文档内容。完整的文档拉取流程如下：

| **步骤** | **接口** | **说明** |
| --- | --- | --- |
| 1. 获取知识库列表 | `GET /v1.0/wiki/spaces` | 列出组织内所有知识库空间，获取 workspaceId |
| 2. 获取节点列表 | `GET /v1.0/wiki/spaces/{workspaceId}/nodes` | 列出指定知识库下的文档节点树，获取 nodeId（workspaceId 来自步骤 1 接口返回的 workspaceId 字段） |
| 3. 获取节点信息 | `GET /v1.0/wiki/nodes/{nodeId}` | 获取单个文档节点的元信息（nodeId 来自步骤 2 接口返回的 nodeId 字段）。注意：节点接口不含文档正文 |
| 4. 读取文档正文 | 钉钉文档内容获取 API | 节点接口只返回元信息不含正文，正文需用节点对应的文档 ID 调用钉钉文档内容获取 API 拉取，用于构建向量索引 |

将拉取的文档内容通过 Embedding 模型（如通义文本嵌入模型 `text-embedding-v3`）转换为向量，存入向量数据库（如 Milvus、FAISS、Elasticsearch），供 Agent 实时检索。

### 配置问答日志表（可选）

如果需要追踪问答效果、识别知识盲区，可在钉钉 AI 表格中创建问答日志表，记录每次问答的详细信息：

| **字段名** | **字段类型** | **说明** |
| --- | --- | --- |
| 提问时间 | 日期时间 | 问题发生的时间 |
| 提问人 | 文本 | 提问员工的姓名 |
| 问题内容 | 多行文本 | 用户的原始问题 |
| 回答内容 | 多行文本 | Agent 生成的回答 |
| 来源文档 | 链接 | 引用的知识库文档链接 |
| 用户反馈 | 单选 | 有帮助 / 未解决 / 答非所问 |
| 所属群 | 文本 | 问题来源的群名称 |

可通过 AI 表格 API `POST /v1.0/notable/bases/{baseId}/sheets/{sheetIdOrName}/records` 写入问答记录（baseId 为多维表 ID，来自多维表 URL 或创建接口返回的 baseId 字段；sheetIdOrName 为数据表 ID 或名称，来自数据表列表接口 `GET /v1.0/notable/bases/{baseId}/sheets` 返回的 id / name 字段）。

## AI 卡片交互配置

知识问答场景推荐使用钉钉 AI 卡片展示回答内容，相比纯文本消息，AI 卡片支持富文本排版、原文链接、反馈按钮等交互元素，用户体验更好。根据不同的交互需求，可选择以下几种卡片类型：

### 卡片类型选型

| **卡片类型** | **适用场景** | **核心能力** | **推荐度** |
| --- | --- | --- | --- |
| **Markdown 卡片** | 标准问答回复 | 支持 Markdown 富文本排版，可内嵌链接、代码块、表格等，适合大多数知识问答场景 | ⭐⭐⭐ 首选 |
| **AI 流式卡片** | 长文本回答、实时生成 | 支持打字机效果逐字输出，适合大模型流式生成场景，用户无需等待完整回答即可开始阅读 | ⭐⭐⭐ 推荐 |
| **交互式按钮卡片** | 需要用户反馈或多步引导 | 在回答下方附带操作按钮（如"有帮助""未解决""查看原文""继续追问"），点击后可触发回调 | ⭐⭐ 增强 |
| **表单卡片** | 信息收集、工单提交 | 支持下拉选择、文本输入等表单组件，适合 Agent 无法回答时引导用户提交工单 | ⭐ 特定场景 |

### 知识问答场景的卡片设计建议

对于知识问答 Agent，推荐组合使用 **AI 流式卡片 + 交互式按钮**，一张卡片中包含以下区域：

| **区域** | **内容** | **说明** |
| --- | --- | --- |
| 标题栏 | 问题摘要 | 简明展示用户提问的核心内容 |
| 回答正文 | Agent 生成的自然语言回答 | 支持 Markdown 格式，流式输出时呈现打字机效果 |
| 引用来源 | 知识库文档标题 + 链接 | 用户可点击直接跳转到原文核实 |
| 反馈按钮 | "有帮助" / "未解决" | 点击后回调记录反馈，用于持续优化回答质量 |
| 追问入口 | "继续追问" 按钮 | 点击后打开与 Agent 的单聊或在群内继续对话 |

### 卡片接入方式

钉钉 AI 卡片通过**卡片模板**进行管理。开发者需要在钉钉开放平台的**卡片平台**中创建卡片模板，定义模板的布局结构和数据变量，然后在 Agent 回复消息时引用模板 ID 并填充实际数据即可渲染卡片。具体操作流程参考钉钉开放平台文档中"互动卡片"章节。

## 验证与测试

完成以上所有配置后，按以下步骤验证 Agent 是否正常工作：

### 基础连通性测试

1. 将机器人添加到测试群。
2. 在群内发送 `@知识问答助手 你好`，确认机器人能收到消息并回复。
3. 也可通过群消息发送 API `POST /v1.0/robot/groupMessages/send` 或群机器人 sessionWebhook 验证群内消息发送能力。

### 知识检索测试

在群内提问一个你确定知识库中有答案的问题，验证：

- Agent 是否能检索到相关文档
- 回答是否准确、完整
- 原文链接是否可正常跳转
- AI 卡片是否正常渲染

### 日志记录验证

如果启用了 AI 表格日志记录，提问后通过 AI 表格查询 API `POST /v1.0/notable/bases/{baseId}/sheets/{sheetIdOrName}/records/list` 检查是否正确写入了问答记录。
