# 告警订阅

## **介绍**

告警订阅用于在连接流运行异常时，通过机器人向指定接收人推送告警消息，帮助开发者第一时间感知故障并介入处理。系统默认保留近 180 天的告警记录。

页面包含两个子标签页：

- **订阅列表**：管理告警规则配置，包括创建、编辑、启用/停用、删除订阅组。
- **告警记录**：查看历史告警推送明细，支持按时间范围筛选，追溯异常事件的时间线与具体内容。

![image](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/3234735871/p557417.png)

## 订阅列表

告警订阅提供多个分组关联群机器人，用于订阅流运行过程中的错误告警信息。以表格形式展示所有已配置的告警订阅组，支持按名称搜索筛选，右上角提供「+ 添加告警订阅」入口。

### 字段说明

| 字段 | 说明 |
| --- | --- |
| 订阅组名称 | 告警规则的名称标识，支持自定义命名以便区分不同业务场景。 |
| 告警对象 | 该订阅组监控的目标，可以是单个连接流、低代码应用，或全局告警。 |
| 告警方式 | 当前固定为「机器人」，即通过钉钉机器人发送告警消息到指定会话或群聊。 |
| 生效范围 | - **连接流**：表示仅监控特定连接流的执行异常； - **组织**：表示监控整个组织范围内的连接流。 |
| 运行状态 | - **已启用**：表示该订阅组处于激活状态，异常时会正常推送告警； - **未启用**：表示已暂停，不会触发告警推送 |
| 创建人 | 该告警订阅组的创建者姓名及主用钉钉账号标识。 |
| 频次 | 告警触发频率统计。 |
| 创建时间 | 订阅组的创建时间戳（格式：YYYY-MM-DD HH:mm:ss） |
| 操作 | 提供**编辑、停用/启用、删除**三个操作入口 |

### 展开详情

部分订阅组行左侧带有展开箭头（∧ / ∨），点击可查看该订阅组下关联的多个告警对象明细。例如a和b两个订阅组均标注「等2项」，表示各自绑定了 2 个告警目标。

![image](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/3234735871/p557418.png)

### 操作说明

- **编辑**：修改订阅组名称、告警对象、接收人、触发条件等配置。
- **停用 / 启用**：临时关闭或恢复该订阅组的告警推送，无需删除即可暂停告警。

  - **已启用**：状态显示蓝色圆点。
  - **未启用**：状态显示灰色圆点。
- **删除**：永久移除该订阅组及其所有配置，删除后不可恢复。

![操作说明](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/3234735871/p1090885.png)

### 添加告警订阅

点击右上角「+ 添加告警订阅」按钮，进入创建流程，需配置以下核心要素：

![添加告警信息按钮](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/3234735871/p1090886.png)

在告警订阅的配置弹窗中，设置告警相关信息：

![image](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/3234735871/p1090882.png)

- **订阅组名称**：自定义命名，建议包含业务关键词便于后续检索（如「订单同步流告警」「CRM数据推送监控」）。
- **告警对象**：选择要监控的连接流、低代码应用，或勾选「全局告警」覆盖全组织。
- **通知方式**：当前支持通过钉钉机器人推送，需提前在目标会话或群聊中配置好机器人 webhook。
- **机器人AccessToken**：填写access\_token值，如何获取access\_token值，请参考[获取自定义机器人 Webhook 地址](../../01-应用开发/01-XOnnmGCTbn-开发指南/0085-obtain-the-webhook-address-of-a-custom-robot.md)。
- **通知频次**：默认值0秒。

## 告警记录

切换到「告警记录」标签页，可查看历史告警推送明细。顶部提供时间范围筛选器（精确到秒），默认展示最近一段时间的记录。

![image](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/3234735871/p1090887.png)

### 字段说明

| 字段 | 说明 |
| --- | --- |
| 订阅组名称 | 触发该条告警的订阅组名称，如「brain事件流告警」。 |
| 告警对象 | 本次告警对应的具体连接流名称，如「查询假期余额」。 |
| 告警时间 | 告警消息实际推送的时间戳（格式：YYYY-MM-DD HH:mm:ss）。 |
| 告警消息 | 告警内容的简要描述，超出部分支持查看完整消息体。 |

### 典型告警消息类型

常见失败原因包括：

- **远程API调用失败**：如 `open api call failed 缺少参数`、`expPayload: {"content":{"errcode":850015,"errmsg"...`，表示下游接口返回错误码，需检查请求参数是否完整。
- **Bad Request**：如 `expPayload: {"content":{"code":"invalidParameter","reque...`，表示请求格式或参数值不合法，需核对 API 文档修正入参。
- **缺失必要字段**：如 `缺失必要字段，请检查入参配置`，表示连接流节点配置中缺少必填项，需回到流编辑器补全配置。
- **出参校验不通过**：如 `调用远程服务业务异常, 出参校验不通过。响应体.是否成功当前值: false, 预期值: true, 所有值: {"traceId"...`，表示下游服务返回了业务层面的失败响应，需结合 traceId 排查服务端日志。

### 分页与筛选

- **时间范围筛选**：顶部日期选择器支持自定义起止时间（精确到秒），便于聚焦特定时间段内的告警事件。
- **分页控件**：底部显示总页数与每页条数，支持翻页浏览更多历史记录。
- **查看全部**：每条告警消息右侧的「查看全部 >」链接可展开完整 JSON 或文本内容，便于复制错误信息用于工单提交或技术排查。

## 使用建议

- **分级告警**：对核心业务流设置独立订阅组并指定专人接收，对非关键流可归入全局告警统一监控，避免告警疲劳。
- **命名规范**：订阅组名称建议采用「业务模块 + 流类型 + 告警级别」的命名约定（如「支付-订单同步-紧急」），便于团队协作时快速识别优先级。
- **定期巡检**：每月检查一次「未启用」状态的订阅组，确认是否为暂停还是遗漏恢复，避免关键流失去监控。
- **结合执行记录**：收到告警后，跳转至「[执行记录](0002-execution-records.md)」页面按时间筛选对应失败记录，定位具体出错节点与原因，形成「告警 → 排查 → 修复」的闭环。
- **告警消息分析**：定期回顾「告警记录」中的高频错误类型，若同一错误反复出现，应优先修复根因而非持续依赖告警通知。

## 常见问题

- **为什么创建了订阅组但没有收到告警？**

  1. 检查「运行状态」是否为「已启用」，未启用状态下不会触发推送。
  2. 确认告警对象的连接流近期是否有实际执行，若流未被触发则不会产生告警。
  3. 验证机器人 webhook 配置是否正确，可在目标会话中手动发送测试消息确认通道畅通。
  4. 检查「生效范围」是否与告警对象匹配，单流监控误选「组织」范围可能导致规则不生效。
- **全局告警和组织级告警有什么区别？**

  - 连接流：仅监控指定的单个或少数几个连接流，适合精细化运维。
  - 组织：监控该组织下所有连接流的执行情况，适合全局兜底监控，但告警量可能较大，建议配合过滤规则使用。
- **如何避免告警风暴？**

  当某个连接流因系统性问题持续失败时，可能短时间内产生大量重复告警。建议：

  - 在订阅组配置中设置告警冷却时间（如相同错误 5 分钟内只推送一次）。
  - 对已知临时性故障的流临时「停用」订阅，修复后再启用。
  - 使用「全局告警」时搭配成功率阈值过滤，仅当成功率低于设定值时才触发告警。
- **告警消息中的「查看全部」能看到什么？**

  点击「查看全部 >」后，会展开完整的告警消息体，通常包含：

  - 错误码（errcode）与错误描述（errmsg）
  - 请求/响应的 payload 片段
  - traceId 等链路追踪标识
  - 出参校验的具体字段对比信息

  这些信息可直接复制用于提交工单或在技术群中协作排查。
