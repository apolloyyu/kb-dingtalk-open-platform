# 项目进度管理 Agent

## **场景介绍**

项目经理最头疼的就是追进度——在群里分配完任务，过两天就忘了谁负责什么、截止日期是哪天，每周五还得手工整理周报。项目进度管理 Agent 让任务管理回归到最自然的沟通方式：在项目群里说一句"把设计评审分给张三，下周三截止"，Agent 自动在 AI 表格中创建任务记录，同时向张三发送钉钉待办提醒。Agent 每日自动扫描逾期和即将到期的任务，在群中推送风险预警；每周五自动汇总本周任务完成情况，生成项目周报发到群里。项目经理随时可以在群里问"现在还有哪些任务没完成""张三手上有几个任务"，Agent 实时查询 AI 表格并以任务看板卡片呈现结果。

## **适用场景**

本方案的核心架构是"群聊 @Agent → 自然语言解析 → AI 表格任务 CRUD + 待办同步 → 定时扫描与汇总 → 卡片反馈"，除项目进度管理外，以下场景也可以复用同一套架构，只需调整 AI 表格的字段结构和自动化规则即可：

![image](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/4613051871/p1081512.png)

| **场景** | **AI 表格数据结构** | **典型指令示例** |
| --- | --- | --- |
| OKR 跟踪管理 | 目标 / 关键结果 / 负责人 / 进度百分比 | "更新Q3的用户增长目标进度到60%""本季度OKR完成情况怎么样" |
| Bug 跟踪管理 | Bug标题 / 严重级别 / 指派人 / 状态 | "提一个P1的Bug给开发组，登录页面白屏""还有几个P0的Bug没修" |
| 需求池管理 | 需求名称 / 优先级 / 提出人 / 排期状态 | "加一个需求：支持批量导出，优先级高""下个迭代排了哪些需求" |
| 招聘进度管理 | 候选人 / 岗位 / 面试阶段 / 面试官 | "王磊的二面安排给李总，下周一""产品经理岗位现在到哪个阶段了" |

## 钉钉集成能力

项目进度管理 Agent 的核心设计思路是**以 AI 表格为数据中枢**——所有任务数据的创建、流转、查询、统计都围绕 AI 表格展开，待办、日历、群消息等能力作为 AI 表格数据变化的下游联动通道。Agent 需要打通以下三层能力：

| **能力层** | **钉钉能力** | **说明** |
| --- | --- | --- |
| **AI 开发套件** | 群机器人 + DWS CLI | 通过钉钉开放平台一键创建群机器人，Agent 通过 DWS CLI 统一调用各产品线能力 |
| **数据中枢层（AI 表格）** | AI 表格全能力：记录 CRUD、字段管理、多视图、仪表盘、自动化 | AI 表格承担项目任务数据库的角色，支撑任务全生命周期管理——从创建、分配、状态流转到统计分析。Agent 通过 DWS CLI 对 AI 表格进行结构化读写，所有业务逻辑的数据源和数据汇都是 AI 表格 |
| **联动能力层** | 待办 + 通讯录 + 日历 + 群消息 | 待办作为 AI 表格任务变化的个人提醒通道；通讯录解析姓名为 userId；日历为里程碑创建日程；群消息推送 AI 表格数据的汇总报告 |
| **用户交互层** | 群聊 @触发 + AI 卡片 | 在群中 @Agent 下达指令，通过任务看板卡片展示 AI 表格中待处理/进行中/已完成任务的摘要视图 |

以上能力中，AI 开发套件和 AI 表格为绝对核心项，待办为推荐项，日历、通讯录搜索和 AI 卡片为增强项。最小可用版本只需完成"群聊接收指令 → AI 表格写入任务 → 文本回复确认"即可上线。

## 开放平台配置（机器人创建）

登录 [钉钉开放平台开发者后台](https://open-dev.dingtalk.com/)，完成以下配置。

### 步骤 1：一键创建 OpenClaw 机器人

在**应用开发**下，点击**立即创建**，选择一键创建 OpenClaw 机器人。在创建界面填写机器人基本信息（如名称填"项目管理助手"），也可直接使用默认的机器人信息，点击**确定**即可。

### 步骤 2：保存应用凭证

OpenClaw 创建成功后，页面会自动展示应用的 `Client ID` 和 `Client Secret`，请妥善保存，后续 DWS CLI 登录认证和 Agent 配置均需使用。

## DWS CLI 接入

DWS（DingTalk Workspace CLI）是钉钉官方开源的命令行工具，将钉钉全产品线能力统一封装为结构化命令。项目进度管理 Agent 通过 DWS CLI 完成任务创建、查询、更新、提醒等全部操作。

### 安装与认证

```
# macOS / Linux 安装
curl -fsSL https://raw.githubusercontent.com/DingTalk-Real-AI/dingtalk-workspace-cli/main/scripts/install.sh | sh

# 登录认证
dws auth login
```

选择组织并授权后，凭证安全存储在本地，后续自动刷新 Token。

### 安装 Agent Skill

```
# 安装 Skill 到 Agent 环境（推荐 mono 模式）
dws skill setup --mode mono --target all --yes
```

### 项目管理场景的核心 DWS 能力

本场景以 AI 表格为数据中枢，辅以待办、通讯录、日历、群聊四个联动产品。AI 表格的 DWS 命令覆盖了从表结构管理到记录操作、视图配置的完整能力，是 Agent 最高频调用的命令集。

**AI 表格（核心数据中枢）**

| **命令** | **能力分类** | **说明** |
| --- | --- | --- |
| `dws aitable base create` | 表格管理 | 创建新的 AI 表格（多表空间），一个项目对应一个 Base |
| `dws aitable table create` | 表格管理 | 在 Base 中创建数据表（如任务表、里程碑表、工时表） |
| `dws aitable field create` | 字段管理 | 为表添加字段，支持文本、单选、日期、数字、关联等类型 |
| `dws aitable field list` | 字段管理 | 查询表的字段结构，Agent 据此解析用户指令并映射到正确字段 |
| `dws aitable record create` | 记录 CRUD | 创建任务记录，支持一次写入多个字段值 |
| `dws aitable record query` | 记录 CRUD | 按条件筛选查询记录——支持按状态、负责人、日期范围、优先级等组合条件过滤 |
| `dws aitable record update` | 记录 CRUD | 更新记录字段值（如状态变更、截止日期调整、负责人变更） |
| `dws aitable record delete` | 记录 CRUD | 删除任务记录（取消任务时使用，建议改为状态标记"已取消"） |
| `dws aitable record list` | 记录 CRUD | 列出表中全部记录，用于统计分析和周报生成 |
| `dws aitable view create` | 视图管理 | 创建自定义视图（看板视图、甘特图视图、日历视图等） |
| `dws aitable view list` | 视图管理 | 查询已有视图列表 |
| `dws aitable dashboard get --base-id <BASE_ID> --dashboard-id <DASHBOARD_ID>` | 仪表盘 | 查询指定仪表盘配置，用于获取统计图表数据（`<BASE_ID>` 为创建 Base 时返回的 ID；`<DASHBOARD_ID>` 可从 AI 表格仪表盘页面 URL 获取） |

**联动产品**

| **产品** | **在项目管理中的角色** | **核心命令** | **说明** |
| --- | --- | --- | --- |
| **待办** | AI 表格任务的个人提醒通道 | `dws todo task create` | 当 AI 表格中创建新任务时，同步向责任人发送待办提醒 |
|  |  | `dws todo task done --task-id <taskId> --status true`（`<taskId>` 为创建待办时返回的任务 ID，建议回写至任务表“待办ID”字段，见 §5.2） | 当 AI 表格中任务状态改为"已完成"时，同步关闭对应待办 |
| **通讯录** | 姓名→userId 解析 | `dws contact user search` | 将"张三"解析为系统 userId，用于 AI 表格记录关联和待办创建 |
| **日历** | 里程碑日程 | `dws calendar event create` | 为 AI 表格中的关键里程碑创建日程，邀请相关干系人 |
| **群聊** | AI 表格数据的展示通道 | `dws chat message send-card` | 将 AI 表格中的查询结果、统计数据以卡片形式推送到群中；纯文本/markdown 消息可降级用 `dws chat message send-by-bot` |

## 核心业务流程

以下为项目进度管理 Agent 的核心业务流程，说明每个流程中 AI 表格如何作为数据中枢与其他能力协同工作。所有流程的起点和终点都是 AI 表格——指令写入 AI 表格，查询从 AI 表格读取，统计基于 AI 表格聚合。

### 任务分配流程

当项目经理在群中说"把设计评审分给张三，下周三截止"时，Agent 依次执行以下操作：

本节及 4.2~4.5 的群消息推送需要两个公共参数：`robotCode` 在创建机器人时返回（见第 2 章保存的应用凭证页面）；群 `openConversationId` 通过 `dws chat search --query "<群名关键词>"` 按关键词搜群获取。

| **步骤** | **操作** | **DWS 命令** | **AI 表格交互** |
| --- | --- | --- | --- |
| 1. 解析姓名 | 将"张三"转换为系统 userId | `dws contact user search --query "张三"` | — |
| 2. 写入 AI 表格 | 在任务表中创建一条新记录 | `dws aitable record create --base-id <BASE_ID> --table-id <TABLE_ID> --records '[{"cells":{"<fld任务名称Id>":"设计评审","<fld负责人Id>":[{"userId":"<userId>","corpId":"<corpId>"}],"<fld截止日期Id>":"2026-06-18","<fld状态Id>":"待处理","<fld优先级Id>":"P1-高","<fld分配人Id>":"李经理","<fld创建日期Id>":"2026-06-12"}}]'`（`<BASE_ID>`/`<TABLE_ID>` 分别为创建 Base/数据表时返回的 ID；cells 的 key 是字段 ID 而非字段名，`<fldXxxId>` 为字段 ID 占位符，先执行 `dws aitable field list` 取字段ID目录；`<userId>`/`<corpId>` 来自步骤 1 通讯录搜索返回） | 写入任务表，自动填充创建日期 |
| 3. 同步待办 | 基于 AI 表格新记录向张三发送待办 | `dws todo task create --title "设计评审" --executors <userId> --due "2026-06-18T18:00:00+08:00"`（`<userId>` 来自步骤 1 的返回；--due 为 ISO-8601 格式，创建成功后返回 taskId） | 待办与 AI 表格记录联动 |
| 4. 回写待办ID | 将步骤 3 返回的 taskId 写回 AI 表格记录 | `dws aitable record update --base-id <BASE_ID> --table-id <TABLE_ID> --records '[{"recordId":"<RECORD_ID>","cells":{"<fld待办IDId>":"<taskId>"}}]'`（`<RECORD_ID>` 为步骤 2 创建记录时返回的 recordId） | 任务记录与待办通过“待办ID”字段建立关联，供后续状态联动关闭待办时取 taskId |
| 5. 群内确认 | 回复任务确认卡片，包含 AI 表格记录链接 | `dws chat message send-card`（纯文本/markdown 可降级用 `dws chat message send-by-bot`） | 卡片中嵌入"在 AI 表格中查看"跳转链接 |

### 任务状态流转

当群成员说"设计评审开始做了"或"把张三的设计评审标记为已完成"时，Agent 更新 AI 表格记录并联动其他能力：

| **步骤** | **操作** | **DWS 命令** | **AI 表格交互** |
| --- | --- | --- | --- |
| 1. 定位记录 | 在 AI 表格中查找目标任务 | `dws aitable record query --base-id <BASE_ID> --table-id <TABLE_ID>` | 按任务名称 + 负责人组合查询，精确定位记录 |
| 2. 更新状态 | 修改任务状态字段 | `dws aitable record update --base-id <BASE_ID> --table-id <TABLE_ID> --records '[{"recordId":"<RECORD_ID>","cells":{"<fld状态Id>":"已完成","<fld完成日期Id>":"2026-06-15"}}]'` | 状态流转：待处理 → 进行中 → 已完成 |
| 3. 联动关闭 | 同步关闭对应的钉钉待办 | `dws todo task done --task-id <taskId> --status true` | AI 表格状态变更触发待办关闭，`<taskId>` 从记录的“待办ID”字段读取 |
| 4. 群内通知 | 通知群成员任务状态变化 | `dws chat message send-by-bot` | 推送变更摘要，包含 AI 表格中的最新状态 |

### 进度查询与统计

当项目经理在群中问"现在还有哪些任务没完成""张三手上有几个任务""P0任务还有哪些"时，Agent 从 AI 表格中按条件查询并组织结果：

| **步骤** | **操作** | **DWS 命令** | **AI 表格交互** |
| --- | --- | --- | --- |
| 1. 条件查询 | 根据用户意图构造查询条件 | `dws aitable record query --base-id <BASE_ID> --table-id <TABLE_ID>` | 支持按状态、负责人、优先级、截止日期范围等组合筛选 |
| 2. 数据聚合 | 将查询结果按维度分组统计 | Agent 内部处理 | 基于 AI 表格返回的记录做分组：按状态统计数量、按人统计负载、按优先级排序 |
| 3. 卡片回复 | 以任务看板卡片在群中展示 | `dws chat message send-card` | 卡片数据全部来源于 AI 表格查询结果，底部附"在 AI 表格中查看完整视图"链接 |

Agent 支持的典型查询模式：

| **用户指令** | **AI 表格查询条件** | **返回格式** |
| --- | --- | --- |
| "还有哪些任务没完成" | 状态 ≠ 已完成 AND 状态 ≠ 已取消 | 按状态分组的任务列表 |
| "张三手上有几个任务" | 负责人 = 张三 AND 状态 ≠ 已完成 | 该成员的任务清单 + 总数 |
| "P0的任务还有哪些" | 优先级 = P0-紧急 AND 状态 ≠ 已完成 | 高优任务列表，按截止日期排序 |
| "本周新建了多少任务" | 创建日期 ≥ 本周一 | 本周任务汇总统计 |
| "这个月完成了多少任务" | 状态 = 已完成 AND 完成日期 ≥ 本月1日 | 已完成任务列表 + 统计数字 |

### 逾期预警流程（每日自动）

Agent 每日定时（如早上 9:30）自动扫描 AI 表格，识别风险任务并推送预警：

| **步骤** | **操作** | **DWS 命令** | **AI 表格交互** |
| --- | --- | --- | --- |
| 1. 扫描逾期任务 | 查询截止日期早于今天且未完成的记录 | `dws aitable record query` | 条件：截止日期 < 今天 AND 状态 ∉ {已完成, 已取消} |
| 2. 扫描即将到期 | 查询截止日期在未来 2 天内的任务 | `dws aitable record query` | 条件：今天 ≤ 截止日期 ≤ 今天+2 AND 状态 ∉ {已完成, 已取消} |
| 3. 计算逾期天数 | 基于 AI 表格记录中的截止日期字段计算 | Agent 内部处理 | 逾期天数 = 今天 - 截止日期，用于排序和标记紧急程度 |
| 4. 推送预警 | 在群中发送风险预警卡片 | `dws chat message send-card` | 卡片按逾期天数排序，红色标记逾期任务、黄色标记即将到期任务 |

### 自动周报流程（每周五）

Agent 每周五下午（如 17:00）从 AI 表格中聚合本周全量数据，自动生成项目周报：

| **步骤** | **操作** | **DWS 命令** | **AI 表格交互** |
| --- | --- | --- | --- |
| 1. 本周新建统计 | 查询本周创建的任务 | `dws aitable record query` | 条件：创建日期 ≥ 本周一 |
| 2. 本周完成统计 | 查询本周完成的任务 | `dws aitable record query` | 条件：完成日期 ≥ 本周一 AND 状态 = 已完成 |
| 3. 当前逾期统计 | 查询所有逾期未完成的任务 | `dws aitable record query` | 条件：截止日期 < 今天 AND 状态 ∉ {已完成, 已取消} |
| 4. 在途任务统计 | 查询所有进行中的任务 | `dws aitable record query` | 条件：状态 = 进行中 |
| 5. 人员负载统计 | 按负责人分组统计任务数量 | Agent 内部处理 | 基于 AI 表格全量记录，按负责人聚合统计 |
| 6. 生成周报 | 大模型根据 AI 表格统计数据生成结构化周报 | Agent 内部处理 | 周报核心数据全部来源于 AI 表格 |
| 7. 群内推送 | 在群中发送项目周报卡片 | `dws chat message send-card` | 卡片附"在 AI 表格中查看仪表盘"链接 |

### 批量任务操作

项目经理经常需要批量调整任务，Agent 支持通过自然语言触发对 AI 表格的批量操作：

| **用户指令** | **Agent 执行的 AI 表格操作** |
| --- | --- |
| "把张三的所有任务转给李四" | 查询负责人=张三的所有未完成记录，逐条更新负责人字段为李四 |
| "下周三的截止日期都推迟到下周五" | 查询截止日期=下周三的记录，批量更新截止日期 |
| "把所有P3的任务优先级提升到P2" | 查询优先级=P3的记录，批量更新优先级字段 |
| "取消所有张三的待处理任务" | 查询负责人=张三 AND 状态=待处理的记录，批量更新状态为已取消 |

## AI 表格数据结构设计

AI 表格是本场景的绝对核心——它不只是一张"记录任务的表"，而是一个完整的项目管理数据库。通过多表关联、多视图切换和仪表盘统计，AI 表格同时服务于 Agent 的数据读写和项目经理的可视化管理需求。

### 多表架构

建议在一个 AI 表格 Base 中创建以下数据表，Agent 通过 `dws aitable table create` 完成初始化：

| **数据表** | **定位** | **与 Agent 的关系** |
| --- | --- | --- |
| **任务表**（主表） | 记录所有任务的全生命周期数据 | Agent 最高频操作的表，所有任务分配、状态流转、查询、统计都基于此表 |
| **里程碑表** | 记录项目的关键节点和交付物 | Agent 在创建日历日程时关联里程碑数据，周报中自动汇总里程碑达成情况 |
| **工时记录表**（可选） | 记录成员每日工时投入 | Agent 根据工时数据生成人员负载分析，辅助任务分配决策 |

### 任务表字段结构

任务表是 Agent 读写最频繁的核心数据表，通过 `dws aitable field create` 创建以下字段：

| **字段名** | **字段类型** | **必填** | **说明** | **Agent 使用场景** |
| --- | --- | --- | --- | --- |
| 任务名称 | 文本 | 是 | 任务的标题描述 | 从用户指令中提取，作为任务的唯一标识 |
| 负责人 | user（成员） | 是 | 任务责任人（成员类型字段） | 从用户指令中提取，结合通讯录解析为 userId 后写入，写入格式：`[{"userId":"...","corpId":"..."}]` |
| 状态 | 单选 | 是 | 待处理 / 进行中 / 已完成 / 已取消 | Agent 状态流转的核心字段，所有查询和统计的基础筛选条件 |
| 优先级 | 单选 | 否 | P0-紧急 / P1-高 / P2-中 / P3-低 | 逾期预警和查询排序的依据，P0/P1 任务在预警卡片中置顶 |
| 截止日期 | 日期 | 是 | 任务的截止时间 | 逾期扫描的核心字段，Agent 每日比对此字段与当前日期 |
| 创建日期 | 日期时间 | 自动 | 任务创建时间（Agent 自动填充） | 周报统计"本周新建任务"的筛选条件 |
| 完成日期 | 日期时间 | 自动 | 任务实际完成时间（状态变为已完成时 Agent 自动填充） | 周报统计"本周完成任务"的筛选条件，也用于计算任务周期 |
| 分配人 | 文本 | 自动 | 分配任务的人（Agent 根据消息发送者自动填充） | 用于追溯任务来源 |
| 待办ID | 文本 | 自动 | 关联的钉钉待办 taskId（创建待办后由 Agent 自动回写，见 §4.1 步骤 4） | 任务状态变为“已完成”时，Agent 据此字段调用 `dws todo task done` 关闭对应待办 |
| 所属里程碑 | 关联 | 否 | 关联里程碑表中的记录 | Agent 根据关联关系在里程碑维度聚合任务完成情况 |
| 备注 | 多行文本 | 否 | 任务的补充说明 | 用户通过自然语言追加的描述信息 |
| 工时预估 | 数字 | 否 | 预估工时（小时） | 用于人员负载分析和排期建议 |

### 里程碑表字段结构

| **字段名** | **字段类型** | **说明** | **Agent 使用场景** |
| --- | --- | --- | --- |
| 里程碑名称 | 文本 | 如"需求评审完成""开发联调完成" | 周报中引用 |
| 计划日期 | 日期 | 里程碑的计划完成日期 | Agent 创建日历日程的日期依据 |
| 实际日期 | 日期 | 里程碑的实际完成日期 | 周报中比对计划与实际，标记延期里程碑 |
| 状态 | 单选 | 未开始 / 进行中 / 已达成 / 已延期 | Agent 自动判断：实际日期 > 计划日期时标记为"已延期" |
| 关联任务 | 关联 | 反向关联任务表 | Agent 统计该里程碑下的任务完成率 |

### 视图配置

AI 表格支持在同一张数据表上创建多种视图，不同视图适用于不同的管理场景。Agent 通过 `dws aitable view create` 创建以下视图，项目经理可在 AI 表格中直接切换查看：

| **视图名称** | **视图类型** | **配置说明** | **适用场景** |
| --- | --- | --- | --- |
| 任务看板 | 看板视图 | 按"状态"字段分栏（待处理/进行中/已完成/已取消） | 项目经理日常跟踪进度，直观看到任务在各状态间的分布 |
| 个人任务 | 看板视图 | 按"负责人"字段分栏 | 查看每个成员的任务负载，识别任务分配是否均衡 |
| 时间线 | 甘特图视图 | 以"创建日期"为开始、"截止日期"为结束 | 可视化项目整体排期，识别任务重叠和资源冲突 |
| 本周任务 | 表格视图 | 筛选条件：截止日期在本周范围内 | 聚焦本周需要完成的任务 |
| 风险任务 | 表格视图 | 筛选条件：已逾期或2天内到期，按优先级降序 | 每日晨会或站会时快速过目风险项 |

Agent 在回复进度查询时，可在卡片底部附上对应视图的跳转链接，引导项目经理在 AI 表格中查看更完整的视图。

### 仪表盘设计

AI 表格的仪表盘功能可将任务数据以图表形式可视化展示。建议配置以下统计图表，Agent 在生成周报时引用仪表盘数据，项目经理也可直接在 AI 表格中查看：

| **图表名称** | **图表类型** | **数据来源** | **展示内容** |
| --- | --- | --- | --- |
| 任务状态分布 | 饼图 | 任务表，按状态字段分组 | 直观展示待处理/进行中/已完成/已取消的占比 |
| 本周任务趋势 | 折线图 | 任务表，按创建日期和完成日期 | 展示每日新建和完成的任务数量走势 |
| 人员任务负载 | 柱状图 | 任务表，按负责人分组，筛选未完成任务 | 展示每个成员当前的任务数量，识别负载失衡 |
| 优先级分布 | 饼图 | 任务表，按优先级字段分组，筛选未完成任务 | 展示P0/P1/P2/P3任务的数量占比 |
| 逾期任务数 | 数字指标 | 任务表，筛选已逾期任务 | 单一数字醒目展示当前逾期任务总量 |
| 里程碑达成率 | 进度条 | 里程碑表，已达成 / 总数 | 展示项目整体里程碑的完成进度 |

仪表盘链接可嵌入 Agent 的周报卡片中，项目经理点击即可跳转到 AI 表格查看交互式图表。

## AI 卡片交互配置

项目进度管理场景推荐使用以下几种 AI 卡片形态：

### 卡片类型选型

| **卡片类型** | **适用场景** | **核心能力** | **推荐度** |
| --- | --- | --- | --- |
| **任务看板卡片** | 进度查询 | 按状态分栏展示任务列表（待处理/进行中/已完成），数据实时读取自 AI 表格，底部附 AI 表格看板视图跳转链接 | ⭐⭐⭐ 首选 |
| **任务确认卡片** | 任务分配 | 展示 Agent 在 AI 表格中新创建的任务详情，附带"开始处理""修改""取消"操作按钮，点击后 Agent 直接更新 AI 表格记录 | ⭐⭐⭐ 推荐 |
| **风险预警卡片** | 逾期提醒 | 基于 AI 表格逾期扫描结果，高亮展示逾期和即将到期的任务，附"在 AI 表格中查看风险视图"链接 | ⭐⭐⭐ 推荐 |
| **项目周报卡片** | 周报推送 | 展示从 AI 表格聚合的本周统计数据（新建/完成/逾期数量），附"查看仪表盘"链接跳转到 AI 表格的可视化图表 | ⭐⭐ 增强 |

### 卡片设计建议

任务看板卡片推荐按以下区域组织内容：

| **区域** | **内容** | **说明** |
| --- | --- | --- |
| 标题栏 | 项目名称 + 任务统计 | 如"XX项目任务看板（3待处理 / 5进行中 / 12已完成）" |
| 待处理列 | 待处理任务列表 | 每条显示：任务名称、负责人、截止日期、优先级标签 |
| 进行中列 | 进行中任务列表 | 同上，即将到期的任务黄色高亮 |
| 已完成列 | 最近完成的任务 | 仅展示本周完成的任务，避免列表过长 |
| 操作区 | "创建任务""查看全部"按钮 | 点击"查看全部"跳转到 AI 表格的任务看板视图，直接在 AI 表格中拖拽管理任务 |

### 卡片接入方式

钉钉 AI 卡片通过**卡片模板**进行管理。开发者需要在钉钉开放平台的**卡片平台**中创建卡片模板，定义模板的布局结构和数据变量，然后在 Agent 回复消息时引用模板 ID 并填充实际数据即可渲染卡片。具体操作流程参考钉钉开放平台文档中"互动卡片"章节。

## 验证与测试

完成以上所有配置后，按以下步骤验证 Agent 是否正常工作：

### 基础连通性测试

1. 将机器人添加到项目测试群。
2. 在群内发送 `@项目管理助手 你好`，确认机器人能收到消息并回复。

### 核心流程测试

逐一验证各核心流程是否正常工作，每个测试都需要同步检查 AI 表格中的数据变化：

| **测试指令** | **预期行为** | **AI 表格验证** |
| --- | --- | --- |
| "@项目管理助手 把登录页面优化分给张三，P1优先级，下周三截止" | Agent 在 AI 表格创建记录 + 向张三发送待办 + 群内回复任务确认卡片 | 打开 AI 表格确认新增一条记录，字段值与指令一致 |
| "@项目管理助手 现在还有哪些任务没完成" | Agent 查询 AI 表格并返回任务看板卡片 | 卡片中的任务列表与 AI 表格中状态≠已完成的记录一致 |
| "@项目管理助手 把张三的登录页面优化标记为已完成" | Agent 更新 AI 表格记录状态 + 关闭对应待办 + 群内确认 | 打开 AI 表格确认该记录状态变为"已完成"，完成日期已自动填充 |
| "@项目管理助手 本周项目进展怎么样" | Agent 统计本周数据并生成周报卡片 | 周报中的统计数字与 AI 表格中按日期筛选的记录数量一致 |
| "@项目管理助手 把张三的所有任务转给李四" | Agent 批量更新 AI 表格中张三的未完成任务 | 打开 AI 表格确认所有原负责人为张三的未完成记录已变更为李四 |

### AI 表格数据完整性验证

在完成上述测试后，进入 AI 表格进行以下数据校验：

1. 打开 AI 表格的**任务看板视图**，确认任务按状态正确分栏展示。
2. 切换到**个人任务视图**，确认每个成员的任务负载与 Agent 回复一致。
3. 查看**仪表盘**，确认各统计图表的数据与实际记录匹配。
4. 检查任务的**创建日期**和**完成日期**是否由 Agent 自动填充。
5. 如果配置了**里程碑表**，确认任务与里程碑的关联关系正确。
